## 02 仪表板「贪玩兰粤」

| 列 | 内容 | 要点 |
|---|---|---|
| 列 1 | 今天 + 耗材提醒 | 动态日期问候卡；智能告警卡只列需处理项（阈值模板驱动） |
| 列 2 | 灯光 | 12 个常用灯/灯组，半宽横向瓷砖 |
| 列 3 | 猫咪 + 双猫厕所 | 三猫合并表格（体重/最近如厕/时长）；铲屎/除臭按钮；PRO 2 摄像头 |
| 列 4 | 拓竹 P1S | 打印仓实况、状态/剩余/喷嘴/热床、任务与层数信息 |

### 技术要点（复用价值高）

- 创建走 **WebSocket API**：`lovelace/dashboards/create` + `lovelace/config/save`，**无需 SSH、无需重启**。脚本见 `scripts/create_dashboard.py` 与 `scripts/update_dashboard.py`。
- 侧边栏排序用 `frontend/set_user_data`（key `sidebar`），**按用户生效**——其他家庭成员账号需各自拖动一次。
- 页面为全实时：前端与 HA 之间 WebSocket 长连接推送状态；摄像头配置 `camera_view: live` 为真视频流；唯一延迟在设备上报频率（蓝牙温湿度计分钟级、Petkit 云端同步）。

## 03 语音 AI 分层架构

核心原则：**快的归本地规则，聪明的归 LLM，慢的归后台 Agent**。千万不要让所有指令都过 LLM。

| 层 | 载体 | 职责 | 延迟 |
|---|---|---|---|
| 反射层 | HA 本地意图引擎（G3 Plus） | 「关外面的灯」「空调 26 度」等高频硬指令。模板+名称槽位严格匹配，断网可用、零 token | < 1 秒 |
| 对话层 | Assist + 本地 LLM（5060 Ti） | 「有点冷，弄暖和点」等理解型指令。管线设「本地优先，未命中落 LLM」，流式边生成边播 | 1–3 秒 |
| 认知层 | 外部 Agent（异步） | 记忆、反思、巡检、跨域长任务。不在语音链路上，想明白了经 announce 主动汇报 | 分钟级 · 异步 |

### 组件选型

| 环节 | 选型 | 说明 |
|---|---|---|
| 语音终端 | HA Voice PE（约 ¥400/台） | ESP32-S3 + 双麦 + XMOS 回声消除；设备端 microWakeWord，唤醒后才推流。**无屏幕**，只有 LED 灯环。可多台，各归属一个区域 |
| STT | SenseVoice / faster-whisper（GPU, Wyoming 协议） | 5060 Ti 上短句 <0.5 秒；中文 SenseVoice 优 |
| LLM | Qwen3-14B Q4（Ollama，**关 thinking**） | 40–60 tok/s，首 token ~0.3 秒；云端兜底 DeepSeek/Qwen API |
| TTS | CosyVoice 2（首选）/ ChatTTS | 流式、带情感、支持副语言 token；替代 Piper/EdgeTTS 去机器人味 |

### 三条已确认的机制细节

- **Thinking 必须关。** 推理链是念不出来的哑巴 token，思考期间音箱死寂。语音任务（调工具+短回复）14B 无思考绰绰有余；真需要深度推理的问题分流给认知层后台跑。
- **文字与工具调用是穿插的。** LLM 输出是 token 流：「好嘞」（即刻进 TTS）→ tool call（HA 即刻执行，~100ms）→「关好了」（继续播）。实际体感：听到应答时灯已经灭了。多设备指令并行调用。
- **「先应一声」不是默认行为**，要在人设提示词里明确要求；代价是约 0.5 秒开口延迟，换拟人感。

### 端到端语音模型（speech-to-speech）的结论

16GB 显存技术上能跑量化后的 MiniCPM-o 2.6 / Qwen2.5-Omni-7B / GLM-4-Voice，但**不上岗**：工具调用能力弱（智能家居命根子）、HA Assist 管线无接入口、智力弱于级联的 14B 文本模型、显存挤兑。可当玩具体验；等开源 omni 工具调用成熟或 HA 开出 speech-to-speech 代理口子时，只需替换「对话层」一个模块。

## 04 语义消歧与拟人化

### 「外面的灯」问题：别名工程优先

- 本地层是严格匹配：「外面」若不是已知区域/实体/别名，槽位解析失败，**整句安全落到 LLM，不会瞎猜错杀**。
- 最佳实践是主动加别名：给阳台/门廊灯组加「外面的灯」「室外灯」等别名 → 本地层半秒执行。**说法固定的模糊词用别名（快），随场景变化的歧义才留给 LLM（聪明）。**

### 给 LLM 的三层上下文

1. **说话人位置**：每台语音卫星归属一个区域，LLM 知道指令来自哪个房间；不带房间名说「开灯」默认操作所在区域。
2. **提示词注入实时状态**：系统提示词是 Jinja 模板，可注入时间、日落、人在传感器分布，以及**家庭词典**（「外面=阳台和入户走廊」这类黑话直接写死）。
3. **结构即上下文**：暴露实体自带区域/楼层归属，命名治理本身就是给 AI 的最大上下文。

### 拟人化：三段流水线逼近端到端体验

ChatGPT 手机端是端到端语音模型，本地 STT→LLM→TTS 天生做不到同款，但两招补掉大半：**口癖在文本层**——人设提示词要求口语化短句、语气词开头；**音色在 TTS 层**——CosyVoice 2 / ChatTTS 支持情感与 `[laughter]`、「嗯」「呃」等副语言 token。配合流式管线可做到 1 秒内开口、全程无空窗。

## 05 安全模型

1. **LLM Tools API 限权**：模型只能通过受限工具集操作，做不到任意 `call_service`。
2. **Expose 白名单**：2806 个实体中只暴露语音需要的几十上百个；门锁、摄像头默认不暴露。**白名单同时是数据边界**——用云端 LLM 时，不暴露即不外泄。
3. **敏感操作走脚本 + 确认**：不暴露锁实体，暴露带条件的脚本；或经 `start_conversation` 二次确认。
4. **令牌隔离**：外部 Agent 用专用令牌可单独吊销；容器隔离运行；规则文件写死「先确认再动作」；**永远不让 Agent 静默修改自动化**。

## 06 贾维斯主动性设计

2025 年后全部为 HA 原生能力：

| 机制 | 能力 | 本宅落地场景 |
|---|---|---|
| `assist_satellite.announce` | 主动播报 | 耗材告警复用仪表板阈值逻辑：「猫厕所 MAX 缺猫砂了」 |
| `assist_satellite.start_conversation` | 主动问询并等回答 | 「客厅灯还开着，需要我关掉吗？」可传 `extra_system_prompt` |
| AI Task（`ai_task.generate_data`） | 定时 AI 分析 | 每日晨间简报；配 LLM Vision 看猫厕所摄像头做异常发现 |

**小爱音箱的废物利用**：两台闲置小爱经 Xiaomi Home 集成 `play_text` 变成「嘴」，覆盖次要房间单向播报。当不了「耳朵」（封闭固件无法做 Assist 卫星），刷机方案（open-xiaoai 等）风险大不推荐。

## 07 记忆与自我进化

模型本身不会学习——「进化」是外挂的反思循环（reflection loop），发生在每晚的批处理里，不在对话现场：

```
行为数据(HA Recorder/Logbook) → 夜间反思(AI Task: 昨日日志+现有档案→更新档案)
        → 习惯档案(几十行 markdown, 可审计可手改) → 注入语音助手 prompt
```

- **即时记忆**：暴露一个「记住」脚本工具——「记住我不喜欢空调直吹」即追加进档案。
- **习惯 → 自动化必须确认制**：反思任务发现稳定规律后走 `start_conversation` 问询，同意才创建。**建议权给 AI，决定权给人。**
- **防误学**：反思 prompt 要求「至少持续两周的规律才记录」；档案每次合并同类项、删过时项。

## 08 认知层与 OpenClaw

HA 原生 hold 得住「神经系统」（反射/对话/主动播报），hold 不住「大脑皮层」（长期记忆、自主循环、跨域长任务）。答案是分层组合——**且控制力不打折**：Agent 经已开启的 MCP Server 接入，Expose 白名单照样生效，语音快路径完全不经它。

### OpenClaw 开箱即得 vs 需自搭的胶水

**开箱即得**：常驻 daemon + heartbeat 心跳巡检、cron 定时、文件式记忆（markdown workspace）、人格/规则文件、MCP 客户端（填 HA 地址+令牌即通）、Telegram 等消息通道。

**胶水（配置级，非开发）**：反思工作流的提示词；开口出口（经 MCP 调 HA announce → 声音从 Voice PE/小爱出）；分工纪律（语音快路径不经它）。

**清醒预期**：通用 Agent 权限面远大于 HA 内置对话代理，对提示词注入敏感——容器隔离、最小权限令牌、不碰门锁、重要动作确认缺一不可。项目迭代快。云端模型跑心跳+反思月成本几十到一二百元，例行任务可指到本地 Ollama。

**值得抄的三个设计**（即使不用它）：记忆就是普通文本文件（可审计）、用心跳而非被动等事件（自主性来源）、人格单独成文件（可版本管理）。

## 09 硬件部署规划

| 设备 | 角色 | 说明 |
|---|---|---|
| NucBox G3 Plus（N150） | 调度中枢 | 纯跑 HAOS：反射层意图、自动化、管线调度。不跑模型。**可完全无头运行**（拔掉键鼠显示器；救援入口 SSH + observer 页 `:4357`；前提：SSH add-on 可用、路由器 DHCP 保留、自动备份开启） |
| 14600KF + 5060 Ti 16G（Windows） | 算力层 + 认知层 | WSL2/Docker 跑 STT/LLM/TTS（Wyoming + Ollama）与 OpenClaw；兼职游戏机。**不需要再买机器**——隔离靠容器+专用令牌 |
| Voice PE ×1–2 | 耳朵 + 嘴 | 对话主力房间；内置小喇叭仅对话级音质，挑剔走 3.5mm 接有源音箱 |
| 闲置小爱 ×2 | 播报出口 | 次要房间单向 announce |
| iPad（闲置） | 中控屏（脸+手） | **当不了语音卫星**——iOS 不允许后台常驻麦克风与唤醒词检测 |

### 5060 Ti 显存账本（16GB）

| 组件 | 显存 | 游戏时处置 |
|---|---|---|
| LLM Qwen3-14B Q4 | ~10 GB | 让路：卸载，语音切云端 |
| STT SenseVoice | ~1 GB | 可常驻（或临时切 CPU） |
| TTS CosyVoice 2 | ~2 GB | 可常驻（Piper 走 CPU 则零占用） |
| OpenClaw Agent | 0（纯 CPU） | 不受影响，E 核承载 |

### 24 小时开机成本

整机空闲约 40–60W，月耗电 30–45 度（电费约 ¥20–30/月）。推理是秒级脉冲，累计可忽略；低载+脉冲工况对硬件损耗温和。

### 系统选型结论

纯 AI 用途的终局是 Ubuntu Server（CUDA/flash-attention/triton 一等公民、无头省 0.5–1GB 显存、kohya/ComfyUI 全原生、Web UI 远程操作、LoRA 训练生图不受影响甚至更顺）；但**因确认要打游戏，定案 Windows + WSL2**——WSL2 内 CUDA 损耗仅个位数百分比。Windows 服务器化三件套必做：**禁睡眠、开机自动登录、Update 延迟重启窗口**，另加 Docker `restart: always` + 任务计划拉起 WSL 实现重启自愈。

## 10 游戏与 AI 共存：游戏模式自动化

思路：游戏时自动降级到云端，结束自动切回本地。语音永远可用，帧率零损。

1. **哨兵**：装 HASS.Agent（Windows 伴侣），上报进程/显存占用为 HA 实体。
2. **触发**：检测到游戏进程 / 显存超阈值。
3. **让路**：REST 命令卸载 Ollama 模型（释放 10GB）；Voice PE 的管线选择实体拨到「云端管线」。
4. **复原**：游戏退出后切回本地管线 + 空请求预热模型。

体感：游戏期间复杂指令延迟 1.5 秒 → 3 秒；「关外面的灯」完全无感（反射层在 G3 Plus 上）。CPU 侧游戏吃 P 核、后台服务挤 E 核，天然不冲突。

## 11 中控屏方案

| 能力 | 安卓平板（Fully Kiosk） | iPad |
|---|---|---|
| 全屏锁定 | ✅ Fully Kiosk（$8 授权） | ✅ Kiosker Pro / 引导式访问 |
| HA 弹窗/跳页/播声 | ✅ browser_mod | ✅ browser_mod（控制浏览器会话，跨平台） |
| HA 远程开关屏幕 | ✅ Fully 官方集成（屏幕/亮度/电量/摄像头动作检测全成实体） | ❌ iOS 无此 API；只能常亮+黑屏保页凑合 |
| 来人亮屏 | ✅ 人在传感器 Pro → 自动化 | ⚠️ 常亮低亮度+快捷指令桥接，链路脆 |
| 语音卫星 | ⚠️ ViewAssist 类方案可合体 | ❌ 不可能 |

**决策**：闲置 iPad 先上岗（Kiosker + browser_mod，七成体验零成本）验证需求；确认刚需后换百元级安卓平板上 Fully 全家桶。终局：**平板当脸和手，旁边立 Voice PE 当耳朵和嘴**，kiosk-mode（HACS）隐藏侧边栏。墙装供电配智能插座做「80% 断充 / 40% 补充」电池保护。

## 12 落地路线图

1. **软件先行（无需等硬件）**：GPU 机 Windows 服务器化 + WSL2 起 Ollama / Wyoming（SenseVoice + CosyVoice 2）；HA 配 Assist 管线（本地优先 + 云端兜底两条）；精选暴露 50–100 个实体；别名工程第一批。手机 App 即可测试全链路。
2. **声音进屋**：购入 Voice PE 1–2 台；两台小爱接为 announce 出口；耗材告警复制成主动播报；上 2–3 个 `start_conversation` 问询场景。
3. **大脑上线**：AI Task 每日晨间简报；习惯档案 + 夜间反思循环 + 「记住」工具；游戏模式自动化（HASS.Agent）。
4. **贾维斯成形**：OpenClaw（或自建认知层）容器化部署接 MCP + Telegram；iPad 中控屏；LLM Vision 看猫实验；音色克隆调「人格」。

## 13 关键决策记录

| 决策 | 理由 |
|---|---|
| 仪表板用原生 sections + tile，不用 Mushroom | 零 HACS 依赖；原生已足够 iOS 感 |
| 语音三层架构，指令不全过 LLM | 延迟与安全的根源治理；本地层断网可用零成本 |
| 本地 LLM 关 thinking | 思考 token 念不出来=音箱死寂；深活分流认知层 |
| 固定模糊词用别名，动态歧义给 LLM | 别名让本地层半秒响应 |
| Agent 与 HA 分层组合而非替代 | 经 MCP 接入控制力不打折；替代语音管线才是打折 |
| 习惯自动化必须人工确认 | 防误学与「家里闹鬼」体验 |
| Agent 与算力同机部署，不加新机器 | localhost 零延迟；隔离靠容器+令牌而非物理分机 |
| GPU 机保留 Windows + WSL2（非 Ubuntu） | 确认有游戏需求；WSL2 CUDA 损耗个位数，LoRA/生图不受影响 |
| 端到端语音模型不上岗 | 工具调用弱 + HA 无接入口 + 智力降级；当玩具养着等拐点 |
| iPad 只当中控屏不当语音卫星 | iOS 禁止后台常驻麦克风 |
| 小爱只当嘴不当耳朵 | 封闭固件；play_text 零风险，刷机不值 |
| G3 Plus 无头运行 | HAOS 本就是电器式系统；SSH + observer:4357 救援 |
