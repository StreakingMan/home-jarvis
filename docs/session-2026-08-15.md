# 会话归档 · 2026-08-15

> 本次会话的完整问答脉络。结论性内容已沉淀进 `blueprint.md`，这里保留探索过程与每个问题的答案要点，供回溯"为什么这么定"。

## 1. 创建仪表板「贪玩兰粤」

**需求**：新仪表板放侧边栏第一位；展示日期/环境/灯光等关键数据、耗材消耗提示、猫和猫砂盆状态；UI 贴近 iOS。中途补充：加 3D 打印机关键状态（带画面）。

**过程与结论**：
- 通过 REST 摸清全部相关实体（Petkit 双猫厕所、三猫传感器、喂食器×2、饮水机、空净、拓竹 P1S、温湿度计、灯组）。
- 用 WebSocket API 创建（`lovelace/dashboards/create` + `lovelace/config/save`），无需 SSH/重启；侧边栏排序用 `frontend/set_user_data` key `sidebar`（按用户生效）。
- 选原生 sections + tile/gauge 卡片（零 HACS 依赖），初版 7 区块。
- 脚本存 `scripts/create_dashboard.py`。

## 2. 优化为单屏

压缩为 4 列紧凑布局（dense_section_placement）：列1 今天+耗材智能告警卡；列2 灯光半宽瓷砖；列3 三猫合并表格+双猫厕所精简操作+PRO2 摄像头；列4 P1S 摄像头+核心瓷砖。打印进度挪到标题徽章。脚本存 `scripts/update_dashboard.py`。

## 3. 仪表板是实时的吗？

是。前端与 HA 走 WebSocket 长连接，状态变化秒级推送；摄像头 `camera_view: live` 是真视频流；`now()` 模板每分钟重渲染。唯一"不实时"在设备上报频率（蓝牙温湿度计分钟级、Petkit 云端同步）。

## 4. 语音 AI 接入的最佳实践（快速响应 + 理解控制 + 安全 + 贾维斯主动性）

- **双层大脑**：本地意图引擎（<1s）优先，未命中落 LLM（2-4s）。千万不要全过 LLM。
- 硬件入口 Voice PE；STT/TTS 中文是难点（HA Cloud 最省心 / 本地 SenseVoice+EdgeTTS）；LLM 国内用 DeepSeek/Qwen API。
- 安全四件套：LLM Tools API 限权、Expose 白名单、敏感操作走脚本+确认、数据边界=暴露列表。
- 主动性三原语：`announce`（主动播报）、`start_conversation`（主动问询并等回答）、AI Task（定时 AI 分析/晨间简报），配 LLM Vision 可看摄像头。

## 5. 「关外面的灯」会被本地层错杀吗？传感器能给 LLM 上下文吗？

- 本地层严格匹配，「外面」不是已知名称就整句落 LLM，不会瞎猜。最佳实践是**别名工程**：固定说法加成别名走本地层秒响应。
- LLM 上下文三层：说话人位置（卫星归属区域）、Jinja 注入实时状态（时间/日落/人在传感器/家庭词典）、区域楼层结构本身。
- 硬件补充确认：HAOS 跑在 NucBox G3 Plus（N150）——本地 STT 用 SenseVoice 勉强，本地 LLM 死心，管线调度无压力。

## 6. GPU 机（14600KF + 5060 Ti 16G）能否 24 小时跑 STT/LLM/TTS？

能且是理想配置：SenseVoice ~1G、Qwen3-14B Q4 ~10G、TTS ~2G 可同时常驻。24h 待机整机 40-60W，电费约 ¥20-30/月，低载+脉冲工况对硬件温和。全链路本地化后隐私/断网顾虑消失。

**Voice PE 原理**：卫星只是耳朵和嘴（设备端 microWakeWord，唤醒后才推流），大脑在服务器；可连多台，各归属一个区域。

**闲置小爱×2**：当不了耳朵（封闭固件），经 `play_text` 当播报出口零风险；刷机（open-xiaoai）不推荐。

## 7. Voice PE 带音响吗？

带小喇叭，对话级音质；3.5mm 可外接有源音箱；TTS 也可重定向到任意 media_player。

## 8. 本地语音能否像 ChatGPT 手机端那样拟人？要开 thinking 吗？

- ChatGPT 语音是端到端模型，本地级联做不到同款，但 CosyVoice 2 / ChatTTS（副语言 token）+ 口语化人设提示词能补大半。
- **thinking 直接关**——思考 token 念不出来=音箱死寂；语音任务 14B 无思考足够；深度问题分流认知层后台跑（跑完播报）。关 thinking 反而更快：首 token 0.3s + 流式管线逐句合成。

## 9. 吐 token 和调 tool 能穿插吗？

能，标准形态：文字（即刻进 TTS）→ tool call（即刻执行 ~100ms）→ 结果回填 → 继续文字。体感"听到应答时灯已灭"。多工具可并行。注意：「先应一声」需在提示词里明确要求，默认多数模型直接吐 tool call。

## 10. 能否不断总结习惯、自我进化？

模型不会学习，靠外挂反思循环：HA Recorder 数据 → 夜间 AI Task 反思 → 习惯档案（markdown）→ 注入 prompt。即时记忆走「记住」脚本工具。习惯→自动化必须 `start_conversation` 人工确认。防误学：两周以上规律才记录、档案定期瘦身。

## 11. 平板中控屏

安卓：Fully Kiosk（全屏+HA 官方集成控屏幕/亮度/动作检测）+ browser_mod（弹窗跳页）+ kiosk-mode + 人在传感器亮屏。ViewAssist 可做"带脸的贾维斯"。iPad 能做七成（Kiosker/引导式访问 + browser_mod），缺口是 iOS 无远程控屏 API。

## 12. iPad 不行吗？

能用但打折。决策：闲置 iPad 先上岗验证需求，确认刚需后换百元安卓平板。iPad **当不了语音卫星**（iOS 禁后台常驻麦克风/唤醒词），终局=平板当脸和手 + Voice PE 当耳朵和嘴。

## 13. HAOS 原生 AI hold 得住愿景吗？要不要完整 agent？OpenClaw 适用吗？

- HA 原生 hold 住神经系统（反射/对话/主动性），hold 不住大脑皮层（长期记忆/自主循环/跨域长任务）。
- 答案是分层组合而非替代：Agent 经 MCP 接入（已开启），Expose 白名单照样生效，**控制力不打折**；打折的做法只有让 agent 接管语音管线。
- OpenClaw = 现成认知层：heartbeat/cron/文件记忆/人格文件/MCP/消息通道开箱即得，胶水只是配置级。风险：权限面大、提示词注入敏感、项目迭代快。三个值得抄的设计：文件式记忆、心跳、人格成文件。

## 14. Agent 部署在哪？要不要再买一台机器？

不需要。Agent 极轻（纯 CPU），与算力同机（GPU 机）部署 localhost 零延迟；隔离靠容器+专用令牌而非物理分机。HAOS 是封闭 appliance 装不了任意软件。Voice PE 没有屏幕（只有 LED 灯环）。Windows 服务器化三件套：禁睡眠、自动登录、Update 延迟重启。

## 15. Ubuntu vs Windows（要 CUDA + LoRA 训练生图）

CUDA/炼丹恰是 Linux 主场（flash-attention/triton 原生、无头省 0.5-1G 显存、kohya/ComfyUI 全支持、Web UI 远程用）。损失只有 Windows 独占 GUI 软件和游戏。

## 16. 偶尔要打游戏，如何共存？

定案 **Windows + WSL2**。显存账本：游戏时只需 LLM（10G）让路，STT/TTS（3G）可留。**游戏模式自动化**：HASS.Agent 上报进程/显存 → HA 触发 → 卸载 Ollama + Voice PE 管线实体拨到云端管线 → 游戏退出复原+预热。语音永远可用，反射层完全无感。

## 18. 本地能跑语音进语音出（端到端）模型吗？

16G 能跑量化 MiniCPM-o 2.6 / Qwen2.5-Omni-7B / GLM-4-Voice / Moshi（英文），但不上岗：工具调用弱、HA 无接入口、智力降级、显存挤兑。当玩具养着；拐点=开源 omni 工具调用成熟或 HA 开 speech-to-speech 代理口子，届时只换对话层模块。

## 19. G3 Plus 可以拔掉键鼠显示器吗？

可以，HAOS 本就无头电器。前提三件事：SSH add-on 可用、路由器 DHCP 保留固定 IP、自动备份开启。救援地址 `http://<HA_IP>:4357`（observer）。需要插回显示器的只剩引导层故障和网络配错到 SSH 不通。
